# ril2-error-regions

Investigation into RIL2 founder-path decode errors — why the CRF
mis-decodes specific genomic intervals for specific founder pairs, even
when raw read support favors the correct founder. Depends on the core
pipeline in `../simval-corpus/` (same environment/setup — see that
README) plus this session's `.lift`-file/anchor-density tooling.

**Start with `results/ril2_error_regions/DIAGNOSTICS.md`** — the working
log for this investigation: pangenome occurrence variance, region
non-continuity/fragmentation, reads-to-intersection convergence, and
anchor-density-vs-error, each scored on 210 real error intervals
(IDX-RIL2 Oh43xIl14H, 0.5x, `--bin-size=1`) against 1000 width-matched
random background regions. Its own conclusion: error regions converge
FASTER to a founder call but land on the WRONG one ~83% of the time; more
pangenome-repetitive, less well-covered by the other founder's own
assembly. What makes B73xCML103 specifically prone to *mutual confusion*
with the reference (rather than the anchor-dropout pattern the other 4
pairs show) is confirmed as genuine large-scale IBD (identity by descent)
for at least one zone (chr5:86–134Mb, 2.8 SNPs/kb vs. 18.8 genome-wide)
but is not otherwise resolved.

## What's here

- **Anchor-density / co-support / touchdown-map tooling**:
  `anchor_density_vs_error.py`, `multi_pair_anchor_generalization.py`,
  `cosupport_vs_error.py`, `bp_distance_decay.py`,
  `founder_divergence_from_b73.py`, `build_touchdown_matrix.py`
  (→ `results/founder_touchdown_map/`), `parse_lift_file.py` (the
  `.lift` binary-format reader these all build on).
- **Region diagnostics**: `region_occ_stats.py`, `region_noncontinuity.py`,
  `reads_to_intersection.py`, `annotate_regions.py`, `local_ssr_content.py`,
  `scan_n_gaps.py`, `sample_background_regions.py`, `chr5_error_profile.py`,
  `chr5_spatial_profile.py`, `error_autocorrelation.py`, `input_autocorrelation.py`.
- **Zero-sequencing-error control** (does the error persist with perfect
  reads? yes — noise is homology-driven, not error-driven):
  `simval_noerr_ril2_reads.py`, `simval_noerr_reads.py` (superseded by
  the former), `simval_noerr_report.py`, `build_ril2_binsize1_batch.py`,
  `build_b73xcml103_binsize1.py`, `score_b73xcml103_noerr_snprc.py` →
  `results/simval_noerr/`.
- **Position-randomization / bin-size probes**: `run_ril2_posrand_sweep.py`,
  `run_ril2_binsize_sweep.py`, `run_ril2_binsize1_posrand_sweep.py`,
  `posrand_jitter_control.py` (noise-floor control for the above),
  `write_jittered_ps4g.py`, `run_ril2_intermediate_coverages.py`.
- **Adaptive-drop bug-fix reruns** (2026-08-24: every RIL2 driver up to
  that point hardcoded `drop_idx=23`/P39; wrong per-sample for most pairs
  — see `../simval-corpus/README.md` gotcha (a)):
  `rebuild_ril2_baseline_adaptive_drop.py`, `rebuild_ril2_binsize1_adaptive_drop.py`.
  **Any result from before 2026-08-24 not regenerated by one of these two
  scripts is suspect.**

All of the above are one-off investigation scripts (a specific question,
often a specific pair/coverage/region), not routine drivers — for the
routine "run any RIL2 pair" path, see `../simval-corpus/README.md`.

## Results

Only findings docs + curated summary tables are committed — the raw
diagnostic JSONs, figure data, and the genome-wide anchor-density
matrices (`founder_touchdown_map/`) are regeneratable via the scripts
above and were kept local-only (still in `grits_workdir/results/`):

- `results/ril2_error_regions/DIAGNOSTICS.md` — the working log (see top
  of this README) + `noerr_0.5x/SUMMARY.{md,tsv}` (the zero-error-control
  summary table).
- `results/ril2_snprc_error_tables.md`, `results/ril2_snprc_results.tsv`
  — the filter-sweep SNP+RefCall tables (built by
  `../simval-corpus/scripts/run_ril2_snp_scoring.py`; the 75 per-row JSON
  outputs it also produces are local-only).
- `results/ril2_binsize_posrand_diagnostics.md`, `results/cml103_chr10_anomaly.md`,
  `results/simval_noerr_oh43xil14h.{md,tsv}`.

## Running

Same environment as `../simval-corpus/README.md`. Every script here
follows the same driver-script convention; most import `simval_paths`/
`heldout_assembly_eval`/`simval_eval_one` from `../simval-corpus/scripts/`
via an explicit `sys.path` entry added when these were brought into the
repo — if you add a new script here that needs one of those, follow the
same pattern (see any existing file's top for the exact line).
