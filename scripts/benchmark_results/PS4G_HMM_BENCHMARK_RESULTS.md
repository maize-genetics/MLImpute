# PS4G HMM Path Finder: Speed Benchmark

Kotlin (`phg_v2`) vs the new PyTorch port (`grits`, PR #187), on CPU and GPU, for haploid
and diploid Viterbi path finding, across four synthetic PS4G input sizes.

## TL;DR

- **Kotlin wins haploid at every size tested** — haploid decoding is cheap enough that
  per-process startup (JVM vs Python/CUDA init) dominates the wall-clock time.
- **Python wins diploid at scale — up to ~10x faster.** Kotlin's diploid Viterbi loop is
  `O(T·S²)` (nested loops over positions × parent-pair states); the PyTorch port vectorizes
  that inner loop into batched tensor ops. At 100,000 positions: **4.0s (Python-CPU) vs
  40.7s (Kotlin)**.
- **GPU never wins for this workload.** Viterbi decoding is inherently sequential across
  positions (each step depends on the previous), so there's one small tensor op per
  position rather than one big batched op — CUDA kernel-launch/dispatch overhead per step
  outweighs the benefit at every size and state-space width tested here. Python-CPU beat
  Python-GPU in all 16 head-to-head comparisons.

## Methodology

- **What's compared**: the original Kotlin CLI (`phg impute-path-from-ps4g`, built from
  `phg_v2`'s `origin/hmm-from-ps4g-claude` branch) vs the new `impute_ps4g.py` PyTorch CLI
  run with `--device cpu` and `--device cuda`.
- **Hardware**: GPU runs used an NVIDIA H200.
- **Timing**: full end-to-end CLI subprocess wall-clock (`time.perf_counter()` around
  `subprocess.run`), i.e. what a real user invoking the CLI would experience — this
  includes JVM startup for Kotlin and Python+CUDA initialization for the GPU runs, since
  both are real per-invocation costs.
- **Repeats**: 3 runs per configuration; **median** is the headline number (min/mean also
  recorded in the raw CSV).
- **Shared CLI parameters**: `--prob-correct 0.98 --prob-same 0.9999 --bin-size 256`
  (diploid runs additionally pass `--inbreed-coef 0.0`).
- **Inputs**: synthetic PS4G files generated by `scripts/generate_synthetic_ps4g.py`, which
  simulates a haplotype trajectory with occasional recombination breakpoints and emits a mix
  of unambiguous and ambiguous (multi-gamete) read-count evidence per binned position.
- **Size tiers**:
  - `small`: 1,000 positions × 10 gametes
  - `medium`: 10,000 positions × 10 gametes
  - `large`: 100,000 positions × 10 gametes
  - `wide`: 500 positions × 20 gametes (probes state-space width independent of sequence
    length — diploid state space is `gametes²`)

## Why the crossover happens

- **Haploid** decoding has a small state space (one state per gamete) and light per-step
  work, so total runtime is small in absolute terms (sub-3s even at 100K positions) and
  dominated by fixed process-startup cost — where the JVM has an edge over Python+torch
  import time.
- **Diploid** decoding has a state space of `gametes²` (parent-pair states) and Kotlin
  implements the transition step as nested loops, giving `O(T·S²)` scalar work in the JVM.
  The PyTorch port replaces those nested loops with vectorized tensor operations, so the
  per-step cost grows far more slowly with `S` and `T`. This is why the diploid speedup
  grows from ~1.2x (small) to over **10x** (large) — it's a genuine algorithmic/vectorization
  win, not just a constant-factor difference.
- **GPU underperforms CPU** here because Viterbi decoding is a sequential scan over
  positions — each position's computation depends on the previous one, so there is no way
  to batch the ~100K sequential steps into one large GPU kernel launch. Per-step tensor ops
  on 100-or-so states are too small to amortize CUDA dispatch overhead, and CUDA context
  initialization adds fixed startup cost on top. CPU tensor ops have much lower per-op
  overhead at this scale.

## Reproducing

```bash
# 1. Generate a synthetic PS4G file
python scripts/generate_synthetic_ps4g.py \
    --positions 100000 --gametes 10 --seed 1 --output /tmp/large.ps4g

# 2. Run the benchmark harness (Kotlin binary + CPU/GPU python interpreters required)
python scripts/benchmark_ps4g_hmm.py \
    --grits-root . \
    --kotlin-bin /path/to/phg_v2/build/install/phg/bin/phg \
    --python-cpu-bin .pixi/envs/default/bin/python \
    --python-gpu-bin .pixi/envs/gpu/bin/python \
    --work-dir /tmp/ps4g_bench \
    --output-csv scripts/benchmark_results/ps4g_hmm_benchmark_$(date +%Y%m%d_%H%M%S).csv
```

An interactive chart version of these results (grouped bar charts, log-scale time axis) is
